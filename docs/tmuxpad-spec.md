# TmuxPad — спецификация и план разработки

> Рабочее название. iPad-клиент для работы с Claude Code в tmux-сессиях на удалённых серверах.
> Повторяет на iPad модель рецепта [`remote-claude-session`](https://github.com/umputun/agterm/tree/master/cookbook/remote-claude-session) из agterm.

---

## 1. Что берём из agterm и рецепта

**agterm** — macOS-терминал (SwiftUI/AppKit + libghostty). Его модель: окно → workspace → session, сайдбар со списком сессий, управление через `agtermctl`.

**Рецепт `remote-claude-session`** — две половины:

| Сторона | Скрипт | Что делает |
|---|---|---|
| Mac | `agt-remote.sh` | пикер (сессии + проекты), открывает вкладку, цикл переподключения ssh |
| Сервер | `agt-remote-host.sh` | `list`, `attach NAME PROJECT`, `kill NAME`, `setup`, `auth`, `clone` |

Ключевая логика серверной части, которую переносим почти без изменений:

- **`list`** — одна команда, TSV:
  - `S <name> <attached> <project>` — tmux-сессии, у которых `session_path` лежит *прямо* в корне проектов (чужие сессии хоста не показываются);
  - `P <project> <path>` — каждая подпапка корня проектов = проект.
- **`attach`** — если сессии нет: `tmux new-session -d -s NAME -c DIR`, затем `send-keys` в pane запуска агента через `sh -c` (агент запускается *внутри шелла*, а не как команда сессии — выход из claude не убивает tmux-сессию). Потом `exec tmux attach-session -d -t =NAME` (`-d` выкидывает чужие клиенты, чтобы размер окна не «сжимался»). Флаг `-d` **не переносим**: у tmux ≥ 3.1 опция `window-size` по умолчанию `latest`, окно берёт размер клиента с последней активностью, и чужие клиенты размеру не мешают (§6.1).
- **Conversation id** привязан к имени сессии: UUID пишется в `~/.agt-remote/NAME.claude`, при пересоздании после ребута — `claude --resume <id>`, иначе `--session-id <id>`.
- **Валидация имён**: сессия `^[A-Za-z0-9_-]{1,64}$`, проект `^[A-Za-z0-9_-][A-Za-z0-9._-]{0,127}$` (`.` и `:` — синтаксис таргетов tmux).
- **`setup`** — `set-clipboard on`, `allow-passthrough on`, `history-limit 50000` в `~/.tmux.conf`; `~/.profile` подхватывает `~/.agt-remote/env` (там `CLAUDE_CODE_OAUTH_TOKEN`). Правку `~/.profile` не переносим: наш `new` сам сорсит env-файл (§7).

Что из рецепта **не переносим** (или переносим иначе):

- Цикл переподключения по exit 255 → на iPad переподключение по событиям жизненного цикла приложения (см. §6).
- Статус-мост через `ssh -R` + python-relay → в v1 нет; в бэклоге — более простой вариант через tmux user option (§10).
- Проброс ssh-agent с Mac для `git` на сервере → на iPad агента нет; у сервера должен быть свой ключ / `gh auth`.
- Компиляция terminfo `xterm-ghostty` → не нужна, используем `TERM=xterm-256color`.

## 2. Цели и не-цели v1

**Цели**
1. Несколько серверов: список в настройках (метка, адрес, порт, пользователь, ключ, корень проектов, команда запуска).
2. Левая панель — дерево **Сервер → Проект → Сессия**, актуальное (живые tmux-сессии с сервера).
3. **Создать сессию**: выбор сервера (если их >1) → выбор проекта (папки сервера) → ввод имени → создаётся tmux-сессия `NAME`, `cd` в папку проекта, запуск `claude` → подключение.
4. **Подключиться**: выбор сервера → выбор из активных сессий → attach. (Плюс просто тап по сессии в дереве.)
5. Центральная область — полноэкранный терминал выбранной сессии.
6. Ключ генерируется на устройстве, публичная часть легко копируется на сервер.
7. Сессия переживает уход приложения в фон, блокировку экрана и смену сети — при возврате тихо переподключаемся.

**Не-цели v1**
- Индикатор статуса агента (active / blocked / done) — бэклог.
- Пуш-уведомления.
- Клонирование репозиториев из приложения, создание папок проектов.
- Сплиты, несколько терминалов на экране одновременно.
- Синхронизация настроек через iCloud.
- iPhone / Mac Catalyst (архитектура не мешает, но не тестируем).

## 3. UX

### 3.1 Раскладка

```
┌───────────────────────┬──────────────────────────────────────────────┐
│ ⌕  Сессии      [+][⇄] │  devbox › api › fix-auth            [⋯]     │
│                       ├──────────────────────────────────────────────┤
│ ▾ devbox              │                                              │
│   ▾ api               │                                              │
│     ● fix-auth        │            Терминал (SwiftTerm)              │
│     ○ refactor        │            tmux attach -t =fix-auth          │
│   ▸ web               │                                              │
│ ▾ hetzner-2           │                                              │
│   ▾ ml-pipeline       │                                              │
│     ○ train-v3        │                                              │
│ ▸ old-vps  ⚠ offline  │                                              │
│                       ├──────────────────────────────────────────────┤
│ ⚙ Настройки           │ [esc][ctrl][tab][↑][↓][←][→][⌥]  (панель)    │
└───────────────────────┴──────────────────────────────────────────────┘
```

- `NavigationSplitView` (sidebar + detail). Сайдбар скрывается — терминал на всю ширину (как zoom в agterm). Хоткей `⌘0` / свайп.
- Сессия: `●` — открыта в этом приложении (есть живой канал), `○` — существует на сервере, не открыта. Подпись: `attached` — к ней подключён клиент не с этого iPad (Mac, другое устройство). Собственные клиенты приложения, включая «зависшие» после сна, не считаются: `list` отдаёт их отдельно (§7). Бейдж информационный: подключение к такой сессии никого не выбивает (§6.1).
- Проекты без сессий по умолчанию скрыты; переключатель «Показывать все проекты» в меню сайдбара.
- Сервер недоступен → строка с `⚠`, остальные серверы работают.
- Pull-to-refresh + автообновление дерева каждые ~10 с, пока приложение активно.

### 3.2 Кнопки и действия

| Где | Действие |
|---|---|
| `[+]` в сайдбаре, `⌘N` | Создать сессию (мастер: сервер → проект → имя) |
| `[⇄]` в сайдбаре, `⌘O` | Подключиться (сервер → список активных сессий) |
| Тап по сессии | Открыть / переключиться |
| Контекст-меню проекта | «Новая сессия здесь» (сервер и проект предзаполнены) |
| Контекст-меню сессии | Открыть · Отключиться (detach) · **Забрать** (`take`, выкидывает чужих клиентов; только при бейдже `attached`, с подтверждением) · **Завершить** (kill, с подтверждением) · Скопировать `tmux attach` |
| Свайп по сессии | Завершить (с подтверждением) |
| `[⋯]` над терминалом | Отключиться · Забрать · Завершить · Переподключить · Размер шрифта |
| `⌘1…⌘9`, `⌘[` / `⌘]` | Переключение между открытыми сессиями |

### 3.3 Мастер «Новая сессия»

1. **Сервер** — шаг пропускается, если сервер один или мастер открыт из контекст-меню.
2. **Проект** — список подпапок корня проектов (из `list`), с поиском.
3. **Имя** — поле, предзаполнено именем проекта (как в рецепте). Пробелы → `-`, валидация по regex вживую, проверка конфликта с существующей сессией (если такая уже есть — предложить подключиться к ней).
4. **Создать** → `host new NAME PROJECT` → открывается терминал с `attach`.

### 3.4 Мастер «Подключиться»

1. Сервер (если >1).
2. Список сессий сервера, сгруппированный по проектам, с пометкой `attached`. Тап → attach.

### 3.5 Терминал

- Аппаратная клавиатура: полный ввод, Esc, Ctrl-комбинации, Option как Meta (настройка). `⌘`-шорткаты приложения перехватываются, остальное уходит в терминал.
- Экранная клавиатура: `inputAccessoryView` с Esc / Ctrl (залипающий) / Tab / стрелки / `|` `~` `/` `-`.
- Скролл одним пальцем → колесо мыши в tmux. SwiftTerm делает это сам: при `allowMouseReporting = true` (по умолчанию) и включённой мыши в приложении вертикальный drag одним пальцем уходит как wheel-события. Со стороны tmux нужен `set -g mouse on` (ставит `setup`). Двумя пальцами SwiftTerm листает свой локальный буфер; под tmux он почти пустой, поэтому основной жест — один палец.
- **Выход из copy-mode.** Ввод в copy-mode tmux **не** выводит из него, клавиши глотаются (проверено на tmux 3.4); выходят `q`, Esc или прокрутка вниз до конца. Поэтому после первого wheel-up приложение считает, что pane в copy-mode, показывает над терминалом чип «Прокрутка ✕» и перед первым вводом с клавиатуры (или по тапу на чип) выполняет `host copy-cancel NAME` через exec-канал, дожидается завершения и только затем отправляет ввод в PTY. Чип скрывается после ввода или тапа; если пользователь сам долистал до конца и copy-mode уже закрылся, чип может остаться до следующего ввода — допустимо, `copy-cancel` в этом случае ничего не делает. Биндинги tmux не трогаем: таблицы клавиш глобальные и сломали бы copy-mode пользователю на Mac.
- Выделение текста → копирование. Буфер обмена с сервера через OSC 52 (`set-clipboard on` уже в рецепте).
- Pinch — размер шрифта. Одно значение на устройство (UserDefaults), общее для всех серверов и сессий; меняется сразу во всех открытых терминалах.
- Поворот, Split View, Stage Manager → `window-change` в PTY → tmux перерисовывает.
- Сессия на сервере завершилась (kill извне / `exit`) → заглушка «Сессия завершена» + кнопки «Создать заново» / «Закрыть».
- Обрыв соединения → полупрозрачная плашка «Переподключение…» поверх последнего экрана, ввод блокируется.
- Канал закрылся, а сессия жива (чужой `attach -d`, например из рецепта agterm на Mac) → один раз молча переподключаемся без `-d`. Если нас выбили повторно в течение минуты → плашка «Отключено другим клиентом» поверх последнего экрана, кнопки «Переподключить» / «Забрать» / «Закрыть» (§6.1).

|---|---|---|
| Метка | `devbox` | да |

| Пользователь | `ubuntu` | да |

| Корень проектов | `~/projects` | да (по умолчанию `projects`) |

| Keepalive, с | `15` | нет |
| Отпечаток хост-ключа | `SHA256:…` (только чтение, кнопка «Сбросить») | — |

Кнопки сервера: **Проверить подключение** · **Подготовить сервер** (установить host-скрипт + `setup`) · **Передать токен Claude** (опционально, аналог `auth`).

**Ключи**: создать (Secure Enclave P-256 или Ed25519) · импортировать (OpenSSH private key, Ed25519) · показать публичный ключ / QR / «Поделиться» · удалить.

**Терминал**: шрифт, размер, тема (светлая/тёмная/как система), Option = Meta, звук bell.

**Диагностика**: журнал событий SSH и host-скрипта (подключения, реконнекты и их причины, коды выхода exec, таймауты пинга, смена сети) с кнопкой «Поделиться». Без секретов и без содержимого терминала. При такой логике переподключений без журнала не разобрать ни один баг с устройства.

### 3.7 Первый запуск (онбординг)

1. Создать ключ → показать публичный ключ + готовую команду для сервера:
   `mkdir -p ~/.ssh && echo '<pubkey>' >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys`
   (кнопки «Скопировать», «Поделиться» — удобно отправить себе на Mac).
2. Добавить сервер.
3. «Проверить подключение» → первый коннект показывает отпечаток хост-ключа → «Доверять».
4. «Подготовить сервер» → отчёт по чеклисту: tmux ≥ 3.1 ✓, claude в login-PATH ✓, корень проектов ✓, проектов найдено: N.

## 4. Технологии

| Слой | Выбор | Почему |
|---|---|---|
| Язык / UI | **Swift 6, SwiftUI**, UIKit где нужно | как agterm; NavigationSplitView даёт сайдбар-дерево из коробки |
| Минимальная ОС | **iPadOS 17** | `@Observable`, SwiftData, актуальный NavigationSplitView |
| Терминал | **[SwiftTerm](https://github.com/migueldeicaza/SwiftTerm)** (MIT) | зрелый VT-эмулятор с готовым `TerminalView` для iOS, мышь, OSC 52, true color; на нём построены коммерческие SSH-клиенты |
| SSH | **[Citadel](https://github.com/orlandos-nl/Citadel)** поверх Apple **swift-nio-ssh** | чистый Swift, exec-каналы + PTY на одном соединении, поддерживает Ed25519 и P-256; никакого libssh2/OpenSSL. Проверено 2026-10-20: Citadel 0.12.1 (swift-nio-ssh 0.3.7, swift-nio 2.104.0, swift-crypto 3.15.1) собирается в режиме Swift 6 на Linux aarch64 в образе `swift:6.1-noble`, чистая сборка 6,5 мин на этом хосте |
| Ключи | **Secure Enclave P-256** (`ecdsa-sha2-nistp256`), запасной вариант Ed25519 в Keychain | ключ SE невозможно извлечь с устройства; swift-nio-ssh принимает SE-ключ напрямую |
| Хранение | Настройки серверов — **SwiftData** (или Codable JSON); секреты — **Keychain** (`kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`) | |
| Сервер | **bash-скрипт** `tmuxpad-host.sh` (порт `agt-remote-host.sh`) | один round-trip на `list`, логика tmux на стороне сервера, легко отлаживать по ssh руками |
| Тесты | Swift Testing / XCTest; интеграционные — Docker-контейнер с sshd + tmux. Ядро (`TmuxPadCore`) собирается и тестируется на Linux (§5.2) | |
| Сборка / раздача | Xcode, XcodeGen (`project.yml`, как в agterm); TestFlight | бесплатный аккаунт = переподпись раз в 7 дней; для нормальной жизни нужен Apple Developer ($99/год) |

**Рассмотренные альтернативы**

- **libghostty** (как в agterm) — лучший рендеринг, но сборка под iOS и интеграция с UIKit для нас не проверены; оставить как эксперимент после v1, если SwiftTerm не устроит. Абстракция `TerminalSurface` (см. §5) сделает замену локальной.
- **WKWebView + xterm.js** — быстро, но хуже с клавиатурой iPad, IME и производительностью.
- **Форк Blink Shell** — GPL, тянет mosh/libssh2, переделка UI сложнее, чем написать своё.
- **Mosh / Eternal Terminal** — не нужны: устойчивость даёт tmux, а переподключение по SSH через ControlMaster-подобный пул быстрое.

## 5. Архитектура приложения

```
App
├── UI (SwiftUI)
│   ├── SidebarView            дерево Server → Project → Session
│   ├── TerminalScreen         UIViewRepresentable вокруг SwiftTerm.TerminalView
│   ├── NewSessionWizard, AttachWizard
│   └── Settings (Servers, Keys, Terminal)
├── State (@Observable)
│   ├── ServerStore            конфиги серверов (SwiftData)
│   ├── TreeModel              снимок list по каждому серверу + статус доступности
│   └── OpenSessionsModel      открытые терминалы, выбранная сессия
├── Core
│   ├── KeyManager             генерация/импорт/экспорт ключей, Keychain, Secure Enclave
│   ├── HostKeyStore           TOFU-отпечатки
│   ├── ConnectionPool         одно SSH-соединение на сервер, keepalive, reconnect
│   ├── HostAPI                list / new / kill / take / copy-cancel / setup / version — exec-каналы, парсинг
│   ├── TerminalSession        PTY-канал ↔ TerminalView, resize, состояние
│   └── HostBootstrap          установка host-скрипта, проверка версии
└── Resources
    └── tmuxpad-host.sh        встроен в бандл, ставится на сервер
```

**Ключевые решения**

- **Одно SSH-соединение на сервер**, внутри — сколько угодно каналов: exec для `list`/`new`/`kill` и PTY-канал на каждую открытую сессию. Аналог `ControlMaster` из рецепта: дерево обновляется за миллисекунды.
- **Открытые терминалы держатся в памяти** (TerminalView + канал) при переключении между ними — переключение мгновенное, без перерисовки. Лимит — 8 открытых (см. «Лимит каналов»); самые старые неактивные отключаются (detach — на сервере ничего не теряется).
- **Лимит каналов.** sshd по умолчанию пускает 10 сессионных каналов на одно соединение (`MaxSessions 10`), exec-каналы тоже считаются. Поэтому на один сервер — не больше 8 PTY-каналов и не больше 2 одновременных exec: `list`, пинг, `new`, `kill` идут через очередь на 2 слота. Отказ сервера открыть канал показываем как ошибку, а не ждём.
- **Keepalive — прикладной пинг.** В swift-nio-ssh и Citadel keepalive нет, а отправить `keepalive@openssh.com` через публичный API swift-nio-ssh нельзя: из глобальных запросов там доступен только TCP-forwarding. Поэтому `ConnectionPool` раз в `keepaliveSeconds` открывает exec-канал с `true` и ждёт ответа 5 с. Если за этот интервал уже прошёл `list`, пинг пропускается. Два неответа подряд — соединение мёртвое (§6). Обрыв, который заметил сам NIO, приходит раньше через `SSHClient.onDisconnect`.
- **Идентификатор устройства** — UUID, создаётся при первом запуске и хранится в Keychain. Передаётся во все exec-строки как `TMUXPAD_CLIENT`, чтобы host-скрипт отличал клиентов этого iPad от чужих (§6.1, §7).
- **PTY**: `TERM=xterm-256color`, `LANG=en_US.UTF-8` (если сервер принимает `AcceptEnv`, иначе через `env` в команде), размер из TerminalView; команда канала — `attach NAME` в форме ниже.
- **Форма exec-строк**: `env TMUXPAD_CLIENT='…' TMUXPAD_PROJECTS='…' TMUXPAD_CMD='…' "$HOME"/.local/bin/tmuxpad-host.sh <cmd> <args>`. `env` не зависит от синтаксиса login-шелла пользователя (csh не понимает `VAR=x cmd`), `$HOME` разворачивает шелл, который sshd запускает для команды. Значения — в одинарных кавычках после валидации (§8).
- **Одно окно.** `UIApplicationSupportsMultipleScenes = false`: второе окно в Stage Manager означало бы два `attach` одной сессии с одного устройства и второй набор каналов.
- **Протокол `TerminalSurface`** (feed bytes / send input / resize / delegate) — чтобы SwiftTerm можно было заменить libghostty без переделки остального.

### 5.1 Модель данных

```swift
struct ServerConfig: Identifiable, Codable {
    var id: UUID
    var label: String
    var host: String            // IP или DNS
    var port: Int = 22
    var user: String
    var keyID: UUID
    var projectsRoot: String = "projects"   // относительно $HOME или абсолютный
    var startCommand: String = "claude"
    var keepaliveSeconds: Int = 15          // интервал exec-пинга (§5)
    var hostKeyFingerprint: String?         // TOFU, SHA256
    var sortIndex: Int
}

struct SSHKeyInfo: Identifiable, Codable {   // приватная часть — только Keychain/SE
    var id: UUID
    var name: String
    var kind: Kind                           // .secureEnclaveP256, .ed25519
    var publicKeyOpenSSH: String
    var createdAt: Date
}

struct RemoteProject: Hashable { var name: String; var path: String }
struct RemoteSession: Hashable {
    var name: String
    var project: String
    var otherClients: Int        // клиенты не с этого устройства; > 0 → подпись `attached`
    var lastActivity: Date       // сортировка в мастере «Подключиться», подпись «активность N мин назад»
}
struct ServerSnapshot { var projects: [RemoteProject]; var sessions: [RemoteSession]; var fetchedAt: Date }
enum ServerReachability { case unknown, online, offline(Error), needsSetup(String) }
```

### 5.2 Разделение по платформам сборки

Слой Core живёт отдельным SwiftPM-пакетом **`TmuxPadCore`** без `import UIKit`/`SwiftUI`, приложение в Xcode подключает его как зависимость. Причина практическая: разработка идёт с Linux-хоста (aarch64, без Xcode), где ralphex исполняет планы, а Mac нужен только для того, что требует Apple-фреймворков. Граница совпадает с границей слоёв из §5 и не даёт её размыть.

| Где собирается и тестируется | Что |
|---|---|
| **Linux и Mac** (`TmuxPadCore`, `swift test`) | `HostAPI` (парсер `list`, коды выхода → ошибки), валидация имён, модели §5.1, `ConnectionPool` на Citadel/swift-nio-ssh (очередь exec на 2 слота, exec-пинг, бэкофф, автомат состояний реконнекта), `HostBootstrap`, протокол `TerminalSurface` и `TerminalSession` без view, ключи Ed25519 через swift-crypto, протоколы хранилищ (`KeyStore`, `HostKeyStore`) с in-memory реализациями для тестов. Интеграционные тесты — против того же Docker-контейнера sshd + tmux, что и host-скрипт |
| **Только Mac** (Xcode-проект) | SwiftUI/UIKit: сайдбар, мастера, `TerminalScreen` на `SwiftTerm.TerminalView`; Keychain и Secure Enclave (реализации `KeyStore`/`HostKeyStore`), SwiftData, `NWPathMonitor`, `scenePhase`, XcodeGen, подпись, симулятор, TestFlight; спайки с железом iPad (клавиатура, поворот, Stage Manager) |

## 6. Жизненный цикл соединения (главное ограничение iPadOS)

iPadOS замораживает приложение в фоне; сокеты умирают в течение ~30 с (в Split View/Stage Manager приложение остаётся активным, пока видно на экране). Устойчивость обеспечивает **tmux на сервере**, приложение лишь переподключается.

| Событие | Поведение |
|---|---|
| `scenePhase → .background` | `beginBackgroundTask` (до ~30 с работы), затем соединения закрываются. Если вернулись раньше — ничего не рвём |
| `scenePhase → .active` | Для каждого сервера с открытыми сессиями: reconnect → `list` → для каждой открытой сессии, которая ещё существует, новый PTY-канал `attach` (без `-d`, tmux отдаёт полный экран); исчезнувшие получают заглушку «Сессия завершена». Чужие клиенты не мешают (§6.1). Плашка «Переподключение…» на время |
| Смена сети (`NWPathMonitor`) | Принудительный reconnect, не дожидаясь keepalive-таймаута |
| Пинг не ответил 2 раза подряд (§5) | Соединение мёртвое → reconnect с бэкоффом 1 → 2 → 5 → 10 с (аналог `AGT_REMOTE_RETRY`) |
| Канал закрылся с выходом 0, приложение detach не делало | Проверяем `list`: сессии нет → заглушка «Сессия завершена»; сессия есть → нас выбил чужой `attach -d`: один раз переподключаемся молча, при повторе в течение минуты — плашка «Отключено другим клиентом» (§6.1) |
| Сервер недоступен | Сервер в дереве `⚠ offline`, прочие работают; открытые терминалы этого сервера — плашка с кнопкой «Повторить» |

### 6.1 Кто владеет сессией

У tmux ≥ 3.1 опция `window-size` по умолчанию `latest`: окно берёт размер клиента с последней активностью. Поэтому к сессии могут быть подключены iPad и Mac одновременно, и «сжатия» окна, ради которого рецепт делает `attach -d`, не происходит; зависший после сна клиент iPad ничего не вводит и размер не диктует. Правило: **приложение подключается без `-d` и выкидывает только собственных клиентов этого устройства; чужой клиент выкидывается только по явному действию пользователя («Забрать»).**

- `attach NAME` перед `exec tmux attach-session -t =NAME` делает `detach-client` для клиентов сессии, у которых PID-файл в `~/.tmuxpad/clients/` содержит текущий `TMUXPAD_CLIENT` (зависшие клиенты этого же iPad), и выставляет `window-size latest` на окне сессии — на случай, если пользователь глобально поставил `smallest`.
- Возврат из фона, смена сети, перезапуск приложения: переподключаемся ко всем открытым сессиям молча, независимо от `others`.
- Нас выбил чужой `attach -d` (канал закрылся с 0, сессия жива): один раз переподключаемся молча. Если это повторилось в течение минуты, на другом устройстве нас выбивают намеренно: плашка «Отключено другим клиентом», кнопки «Переподключить» / «Забрать» (`take`) / «Закрыть».
- «Забрать» в контекст-меню сессии и в меню `[⋯]` — единственный путь к `attach -d` (`take` в §7). Тап по сессии в дереве и мастер «Подключиться» делают обычный `attach`.
- Бейдж `attached` в дереве информационный: рядом работает кто-то ещё.
- Цена подхода: когда печатают с Mac, окно принимает размер Mac, и на iPad появляется незаполненная область до следующего ввода с iPad. Осознанный компромисс в пользу «никого не выбиваем».

Почему нельзя считать чужих просто по `session_attached`: после сна iPad сервер ещё долго держит его мёртвое соединение. Без `ClientAliveInterval` в sshd это до TCP-таймаута, то есть часы. Всё это время tmux считает старый клиент iPad подключённым, и сессия выглядела бы занятой «кем-то». Поэтому host-скрипт помечает клиентов приложения (`attach` в §7), `list` считает только чужих, а `attach` выкидывает своих зависших. Чистое закрытие соединения при уходе в фон (§6) делает зависшие клиенты редкостью: они остаются только после убийства приложения системой или обрыва сети.

## 7. Серверная часть: `tmuxpad-host.sh`

Порт `agt-remote-host.sh` (MIT, с атрибуцией). Ставится в `~/.local/bin/tmuxpad-host.sh`, состояние в `~/.tmuxpad/`. **Совместимость с рецептом agterm не нужна** — свои пути, свои форматы, никаких оглядок на `~/.agt-remote`.

```
tmuxpad-host.sh version              → "tmuxpad-host 1"         (проверка/обновление скрипта)
tmuxpad-host.sh list                 → TSV, см. ниже
tmuxpad-host.sh new NAME PROJECT     → создать tmux-сессию, запустить агента; exit 3 если уже есть
tmuxpad-host.sh attach NAME          → выкинуть своих зависших клиентов, exec tmux attach-session -t =NAME; exit 4 если нет
tmuxpad-host.sh take NAME            → то же, но attach-session -d: выкидывает всех (кнопка «Забрать»)
tmuxpad-host.sh copy-cancel NAME     → tmux send-keys -t '=NAME:' -X cancel; всегда exit 0 (§3.5)
tmuxpad-host.sh kill NAME            → убить сессию и её state-файлы
tmuxpad-host.sh setup                → идемпотентная подготовка, отчёт-чеклист
tmuxpad-host.sh auth                 → токен Claude со stdin → ~/.tmuxpad/env (0600)
tmuxpad-host.sh doctor               → проверки: tmux≥3.1, claude в login PATH, корень проектов
```

Переменные из окружения команды (приложение передаёт их явно в exec-строке): `TMUXPAD_PROJECTS`, `TMUXPAD_CMD`, `TMUXPAD_CLIENT` (UUID устройства, §5; скрипт проверяет его по regex UUID).

**`attach NAME`** по шагам:
1. `tmux has-session -t =NAME` → иначе `exit 4`;
2. чистка: файлы в `~/.tmuxpad/clients/`, PID-ов которых нет в `tmux list-clients`, удаляются (то же делает `list`);
3. свои зомби: `tmux list-clients -t =NAME -F '#{client_pid}\t#{client_tty}'`, для PID-ов, чей файл содержит текущий `TMUXPAD_CLIENT`, — `tmux detach-client -t <tty>`;
4. `tmux set -t =NAME mouse on` и `tmux set -w -t '=NAME:' window-size latest`;
5. UUID устройства → `~/.tmuxpad/clients/$$`; из-за `exec` PID tmux-клиента совпадает с `$$`, так что файл однозначно связывает клиента tmux с устройством;
6. `exec tmux attach-session -t =NAME`.

**`take NAME`** — те же шаги с `attach-session -d`.

Таргеты pane и окна в tmux-командах — `=NAME:`: голый `=NAME` для `send-keys -X`, `set -w` и подобных трактуется как pane и даёт `can't find pane` (проверено на 3.4). Для `has-session`, `attach-session`, `kill-session` и session-опций — `=NAME`.

**`list`** — расширенный формат (версионированный заголовок, чтобы менять без поломок):
```
V	1
S	<name>	<others>	<project>	<activity_epoch>
P	<project>	<abs_path>
```
tmux-формат сессий: `#{session_name}\t#{session_path}\t#{session_activity}`; фильтр «path лежит прямо в корне проектов» — как в рецепте, но корень и `session_path` сравниваются после `realpath`, иначе симлинк в пути ломает фильтр. `activity` нужен приложению для сортировки сессий в мастере «Подключиться» и подписи «активность N мин назад». `others` — число клиентов сессии из `tmux list-clients -F '#{session_name}\t#{client_pid}'`, у которых нет файла в `~/.tmuxpad/clients/` с текущим `TMUXPAD_CLIENT`. Клиенты рецепта agterm и обычного `tmux attach` с Mac всегда чужие.

**`new NAME PROJECT`** — по шагам из запроса:
1. валидация имени и проекта, проверка `[[ -d $PROJECTS/$PROJECT ]]`;
2. `tmux has-session -t =NAME` → если есть, `exit 3` (приложение предложит подключиться);
3. `pane=$(tmux new-session -d -P -F '#{pane_id}' -s NAME -c DIR)` — tmux-сессия с именем, сразу в папке проекта; затем `tmux set -t =NAME mouse on`;
4. UUID разговора: `~/.tmuxpad/NAME.claude` — строка `<uuid>\t<project>`, создаётся при первом `new`, хранится до `kill`. Если файл есть, но проект в нём другой (сессию убили руками через tmux и создали с тем же именем в другом проекте) — новый UUID и перезапись файла: Claude Code резюмит по UUID из любого каталога (проверено на 2.1.304), и без этого в новый проект приехал бы разговор старого. Источник UUID — `/proc/sys/kernel/random/uuid` (есть на любом Linux), `uuidgen` не нужен;
5. `tmux send-keys -t $pane "sh -c '[ -f ~/.tmuxpad/env ] && . ~/.tmuxpad/env; exec $CMD <флаги>'" Enter` — claude стартует внутри login-шелла, поэтому его выход не убивает tmux-сессию.

**Имя Claude-сессии = имя tmux-сессии.** Claude Code умеет задавать имя при старте: `claude -n NAME` (`--name`); оно видно в строке промпта, в `/resume`-пикере и работает как `claude --resume NAME`. Флаги запуска:

| Ситуация | Команда |
|---|---|
| Новая сессия | `claude -n NAME --session-id <uuid>` |
| Сессия пересоздаётся (ребут сервера), транскрипт `~/.claude/projects/*/<uuid>.jsonl` есть | `claude --resume <uuid>` (имя хранится в самом разговоре). Каталог транскрипта — абсолютный путь проекта, где `/` и `.` заменены на `-`; искать можно глобом, `--resume` всё равно находит транскрипт из любого каталога (проверено на 2.1.304) |
| Транскрипта нет (удалён / истёк срок хранения 30 дней) | как новая, с **новым** UUID и перезаписью `NAME.claude` — одно правило на оба случая «другой проект» и «нет транскрипта». Занятый `--session-id` ошибки не даёт (проверено на 2.1.304), но два транскрипта с одним ID в разных каталогах путают `--resume` |

Почему резюмим по UUID, а не `--resume NAME`: имя может совпасть с разговором, начатым руками в том же проекте, и тогда вместо резюма откроется пикер; UUID однозначен. Если сессию переименовали изнутри (`/rename`), имя tmux-сессии в дереве остаётся прежним — источником правды для приложения служит tmux.

В фазе 0 проверить на серверах версию Claude Code (`claude --version`) и что `-n` вместе с `--session-id` принимается; если сервер на старой версии без `-n` — `doctor` предупреждает, сессия стартует без имени.

Разделение `new` и `attach` (в рецепте это одна команда) нужно, чтобы приложение отличало «создал» от «подключился» и корректно показывало конфликт имён.

**`setup`** пишет в `~/.tmux.conf` помеченный идемпотентный блок: `set-clipboard on`, `history-limit 50000`, и `allow-passthrough on` только при `tmux -V` ≥ 3.3. Глобально `mouse` **не** включает: это сломало бы выделение мышью в tmux-сессиях пользователя на Mac; `mouse` — session-опция, её ставят `new` и `attach` на конкретную сессию. `~/.profile` не трогает: `new` сам сорсит `~/.tmuxpad/env`. Не трогает `~/.claude/settings.json` (хуки статуса — бэклог), `known_hosts` и ssh-agent.

**Установка из приложения**: exec `mkdir -p ~/.local/bin && cat > ~/.local/bin/tmuxpad-host.sh && chmod +x …` со скриптом в stdin, затем `setup`. При каждом подключении `version` → если старше бандла, предложить обновить.

**Требования к серверу**: Linux, bash, tmux ≥ 3.1 (нужен `window-size latest`; Ubuntu 22.04 с 3.2a подходит, `allow-passthrough` ставится только от 3.3), Claude Code в PATH login-шелла и залогинен (`claude` → `/login` или `auth` с токеном из `claude setup-token`), sshd с разрешённым входом по ключу `ecdsa-sha2-nistp256` или `ssh-ed25519` (по умолчанию в OpenSSH — да). Для `git push` из сессии — собственный ключ/`gh auth` на сервере (агента с iPad не пробрасываем).

## 8. Безопасность

- Приватный ключ: Secure Enclave (неизвлекаемый) или Keychain `ThisDeviceOnly`; никогда не логируется, не попадает в бэкапы.
- Опционально: Face ID перед первым использованием ключа в сессии приложения (`LAContext` / access control у SE-ключа).
- Хост-ключ: TOFU с явным подтверждением отпечатка; смена отпечатка → блокирующее предупреждение, подключение только после ручного «Сбросить».
- Без паролей в v1 (только ключи) — меньше поверхность и не надо хранить пароли.
- Имена сессий/проектов валидируются и в приложении, и в скрипте; в exec-строки ничего не подставляется без экранирования (одинарные кавычки + запрет `'`, как в рецепте).
- Токен Claude (`auth`) передаётся через stdin, не в аргументах; на сервере `0600`.

## 12. Риски

| Риск | Вероятность | Митигирование |
|---|---|---|
| Ввод в SwiftTerm с аппаратной клавиатурой iPad (Esc, Ctrl, IME) имеет шероховатости | средняя | проверить в фазе 0; `pressesBegan` для недостающих клавиш; запасной вариант — libghostty |
| API Citadel для PTY меняется между версиями | средняя | зафиксировать версию; узкий адаптер `SSHTransport` поверх swift-nio-ssh |
| Сервер не принимает ECDSA P-256 | низкая | Ed25519 как альтернативный тип ключа |
| Фоновые ограничения iPadOS раздражают частыми переподключениями | высокая (by design) | быстрый reconnect + tmux; mosh в бэклог только если будет реально мешать |
| Подпись: без платного аккаунта приложение живёт 7 дней | — | Apple Developer Program или переустановка из Xcode |

## 13. Открытые вопросы

1. Распространение: только для себя (Xcode/TestFlight) или App Store — влияет на онбординг и требования к приватности.

**Решено:**
- Совместимость с рецептом agterm не нужна; Claude-сессия получает имя tmux-сессии через `claude -n NAME`.
- 2026-10-20: `attach` без `-d`, чужих выкидывает только `take` по кнопке «Забрать»; размер окна отдаём `window-size latest` (§6.1).
- 2026-10-20: выход из copy-mode — `copy-cancel` на стороне приложения перед первым вводом после скролла; биндинги tmux не трогаем (§3.5).
- 2026-10-20: порог tmux 3.1 вместо 3.3, `allow-passthrough` условно (§7).
- 2026-10-20: `mouse on` только на сессиях приложения, `setup` не трогает `~/.profile` и глобальный `mouse` (§7).
- 2026-10-20: `NAME.claude` хранит проект; смена проекта или потеря транскрипта → новый UUID (§7).
- 2026-10-20: одно окно приложения, exec-строки через `env`, журнал диагностики в v1 (§5, §3.6).
