# TmuxPad — спецификация и план разработки

> Рабочее название. iPad-клиент для работы с Claude Code в tmux-сессиях на удалённых серверах.
> Повторяет на iPad модель рецепта [`remote-claude-session`](https://github.com/umputun/agterm/tree/master/cookbook/remote-claude-session) из agterm.

---

## 1. Что берём из agterm и рецепта

**agterm** — macOS-терминал (SwiftUI/AppKit + libghostty). Его модель: окно → workspace → session, сайдбар со списком сессий, управление через `agtermctl`.

**Рецепт `remote-claude-session`** — две половины:

| Сторона | Скрипт | Что делает |
|---|---|---|
| Mac | `agt-remote.sh` | пикер (сессии + проекты), открывает вкладку, цикл переподключения ssh |
| Сервер | `agt-remote-host.sh` | `list`, `attach NAME PROJECT`, `kill NAME`, `setup`, `auth`, `clone` |

Ключевая логика серверной части, которую переносим почти без изменений:

- **`list`** — одна команда, TSV:
  - `S <name> <attached> <project>` — tmux-сессии, у которых `session_path` лежит *прямо* в корне проектов (чужие сессии хоста не показываются);
  - `P <project> <path>` — каждая подпапка корня проектов = проект.
- **`attach`** — если сессии нет: `tmux new-session -d -s NAME -c DIR`, затем `send-keys` в pane запуска агента через `sh -c` (агент запускается *внутри шелла*, а не как команда сессии — выход из claude не убивает tmux-сессию). Потом `exec tmux attach-session -d -t =NAME` (`-d` выкидывает чужие клиенты, чтобы размер окна не «сжимался»). Флаг `-d` **не переносим**: у tmux ≥ 3.1 опция `window-size` по умолчанию `latest`, окно берёт размер клиента с последней активностью, и чужие клиенты размеру не мешают (§6.1).
- **Conversation id** привязан к имени сессии: UUID пишется в `~/.agt-remote/NAME.claude`, при пересоздании после ребута — `claude --resume <id>`, иначе `--session-id <id>`.
- **Валидация имён**: сессия `^[A-Za-z0-9_-]{1,64}$`, проект `^[A-Za-z0-9_-][A-Za-z0-9._-]{0,127}$` (`.` и `:` — синтаксис таргетов tmux).
- **`setup`** — `set-clipboard on`, `allow-passthrough on`, `history-limit 50000` в `~/.tmux.conf`; `~/.profile` подхватывает `~/.agt-remote/env` (там `CLAUDE_CODE_OAUTH_TOKEN`). Правку `~/.profile` не переносим: наш `new` сам сорсит env-файл (§7).

Что из рецепта **не переносим** (или переносим иначе):

- Цикл переподключения по exit 255 → на iPad переподключение по событиям жизненного цикла приложения (см. §6).
- Статус-мост через `ssh -R` + python-relay → в v1 нет; в бэклоге — более простой вариант через tmux user option (§10).
- Проброс ssh-agent с Mac для `git` на сервере → на iPad агента нет; у сервера должен быть свой ключ / `gh auth`.
- Компиляция terminfo `xterm-ghostty` → не нужна, используем `TERM=xterm-256color`.

## 2. Цели и не-цели v1

**Цели**
1. Несколько серверов: список в настройках (метка, адрес, порт, пользователь, ключ, корень проектов, команда запуска).
2. Левая панель — дерево **Сервер → Проект → Сессия**, актуальное (живые tmux-сессии с сервера).
3. **Создать сессию**: выбор сервера (если их >1) → выбор проекта (папки сервера) → ввод имени → создаётся tmux-сессия `NAME`, `cd` в папку проекта, запуск `claude` → подключение.
4. **Подключиться**: выбор сервера → выбор из активных сессий → attach. (Плюс просто тап по сессии в дереве.)
5. Центральная область — полноэкранный терминал выбранной сессии.
6. Ключ генерируется на устройстве, публичная часть легко копируется на сервер.
7. Сессия переживает уход приложения в фон, блокировку экрана и смену сети — при возврате тихо переподключаемся.

**Не-цели v1**
- Индикатор статуса агента (active / blocked / done) — бэклог.
- Пуш-уведомления.
- Клонирование репозиториев из приложения, создание папок проектов.
- Сплиты, несколько терминалов на экране одновременно.
- Синхронизация настроек через iCloud.
- iPhone / Mac Catalyst (архитектура не мешает, но не тестируем).

## 3. UX

### 3.1 Раскладка

```
┌───────────────────────┬──────────────────────────────────────────────┐
│ ⌕  Сессии      [+][⇄] │  devbox › api › fix-auth            [⋯]     │
│                       ├──────────────────────────────────────────────┤
│ ▾ devbox              │                                              │
│   ▾ api               │                                              │
│     ● fix-auth        │            Терминал (SwiftTerm)              │
│     ○ refactor        │            tmux attach -t =fix-auth          │
│   ▸ web               │                                              │
│ ▾ hetzner-2           │                                              │
│   ▾ ml-pipeline       │                                              │
│     ○ train-v3        │                                              │
│ ▸ old-vps  ⚠ offline  │                                              │
│                       ├──────────────────────────────────────────────┤
│ ⚙ Настройки           │ [esc][ctrl][tab][↑][↓][←][→][⌥]  (панель)    │
└───────────────────────┴──────────────────────────────────────────────┘
```

- `NavigationSplitView` (sidebar + detail). Сайдбар скрывается — терминал на всю ширину (как zoom в agterm). Хоткей `⌘0` / свайп.
- Сессия: `●` — открыта в этом приложении (есть живой канал), `○` — существует на сервере, не открыта. Подпись: `attached` — к ней подключён клиент не с этого iPad (Mac, другое устройство). Собственные клиенты приложения, включая «зависшие» после сна, не считаются: `list` отдаёт их отдельно (§7). Бейдж информационный: подключение к такой сессии никого не выбивает (§6.1).
- Проекты без сессий по умолчанию скрыты; переключатель «Показывать все проекты» в меню сайдбара.
- Сервер недоступен → строка с `⚠`, остальные серверы работают.
- Pull-to-refresh + автообновление дерева каждые ~10 с, пока приложение активно.

### 3.2 Кнопки и действия

| Где | Действие |
|---|---|
| `[+]` в сайдбаре, `⌘N` | Создать сессию (мастер: сервер → проект → имя) |
| `[⇄]` в сайдбаре, `⌘O` | Подключиться (сервер → список активных сессий) |
| Тап по сессии | Открыть / переключиться |
| Контекст-меню проекта | «Новая сессия здесь» (сервер и проект предзаполнены) |
| Контекст-меню сессии | Открыть · Отключиться (detach) · **Забрать** (`take`, выкидывает чужих клиентов; только при бейдже `attached`, с подтверждением) · **Завершить** (kill, с подтверждением) · Скопировать `tmux attach` |
| Свайп по сессии | Завершить (с подтверждением) |
| `[⋯]` над терминалом | Отключиться · Забрать · Завершить · Переподключить · Размер шрифта |
| `⌘1…⌘9`, `⌘[` / `⌘]` | Переключение между открытыми сессиями |

### 3.3 Мастер «Новая сессия»

1. **Сервер** — шаг пропускается, если сервер один или мастер открыт из контекст-меню.
2. **Проект** — список подпапок корня проектов (из `list`), с поиском.
3. **Имя** — поле, предзаполнено именем проекта (как в рецепте). Пробелы → `-`, валидация по regex вживую, проверка конфликта с существующей сессией (если такая уже есть — предложить подключиться к ней).
4. **Создать** → `host new NAME PROJECT` → открывается терминал с `attach`.

### 3.4 Мастер «Подключиться»

1. Сервер (если >1).
2. Список сессий сервера, сгруппированный по проектам, с пометкой `attached`. Тап → attach.

### 3.5 Терминал

- Аппаратная клавиатура: полный ввод, Esc, Ctrl-комбинации, Option как Meta (настройка, по умолчанию включено). `⌘`-шорткаты приложения перехватываются, остальное уходит в терминал.
- Экранная клавиатура: `inputAccessoryView` с Esc / Ctrl (залипающий) / Tab / стрелки / `|` `~` `/` `-`. Это встроенный `TerminalAccessory` SwiftTerm, он стоит у `TerminalView` по умолчанию; своя панель не нужна.
- Скролл одним пальцем → колесо мыши в tmux. SwiftTerm делает это сам начиная с 1.99.0: при `allowMouseReporting = true` (по умолчанию) и включённой мыши в приложении вертикальный drag одним пальцем уходит как wheel-события. В 1.20.0 и раньше тот же drag шлёт нажатие и движение кнопки, а не колесо (проверено по исходникам 2026-10-20), поэтому нижняя граница — 1.99.0. Со стороны tmux нужна мышь в сессии: `new` и `attach` ставят session-опцию `mouse on` (`set -t =NAME: mouse on`); глобальный `mouse` в `~/.tmux.conf` `setup` не трогает. Двумя пальцами SwiftTerm листает свой локальный буфер; под tmux он почти пустой, поэтому основной жест — один палец.
- **Выход из copy-mode.** Ввод в copy-mode tmux **не** выводит из него, клавиши глотаются (проверено на tmux 3.4); выходят `q`, Esc или прокрутка вниз до конца. Поэтому после первого wheel-up приложение считает, что pane в copy-mode, показывает над терминалом чип «Прокрутка ✕» и перед первым вводом с клавиатуры (или по тапу на чип) выполняет `host copy-cancel NAME` через exec-канал, дожидается завершения и только затем отправляет ввод в PTY. Чип скрывается после ввода или тапа; если пользователь сам долистал до конца и copy-mode уже закрылся, чип может остаться до следующего ввода — допустимо, `copy-cancel` в этом случае ничего не делает. Если сам `copy-cancel` не удался (обрыв соединения, таймаут), ввод всё равно уходит, а чип возвращается: следующий ввод, в том числе после переподключения, повторит `copy-cancel`. Биндинги tmux не трогаем: таблицы клавиш глобальные и сломали бы copy-mode пользователю на Mac.
- **Мышь и клавиатура идут одним путём.** SwiftTerm отдаёт и ввод, и мышиные отчёты (колесо, тап) через один делегатный `send`. Поэтому ядро разбирает исходящие байты (`MouseReport`: SGR `ESC [ < b ; x ; y M|m` и X10 `ESC [ M b x y`). Отчёт колеса вверх включает чип, прочие мышиные отчёты уходят в PTY как есть и `copy-cancel` не вызывают: иначе второй же шаг прокрутки выводил бы pane из copy-mode. Всё остальное — ввод, перед первым после скролла идёт `copy-cancel`.
- Выделение текста → копирование. Буфер обмена с сервера через OSC 52 (`set-clipboard on` уже в рецепте) — только запись и только UTF-8: читать буфер iPad сервер не может (§8). Ссылки из терминала открываются только `http`/`https`.
- Pinch — размер шрифта. Одно значение на устройство (UserDefaults), общее для всех серверов и сессий; меняется сразу во всех открытых терминалах. По умолчанию 14 pt, диапазон 9…32, шаг pinch — 1 pt; звонок по умолчанию включён.
- Поворот, Split View, Stage Manager → `window-change` в PTY → tmux перерисовывает.
- Сессия на сервере завершилась (kill извне / `exit`) → заглушка «Сессия завершена» + кнопки «Создать заново» / «Закрыть». «Создать заново» — `new` с тем же именем и проектом из снимка дерева на момент открытия, затем `attach`; сессию уже создали заново — не ошибка; проекта больше нет на сервере — алерт «Проект P не найден на сервере»; проект на момент открытия неизвестен — «Проект сессии неизвестен».
- Обрыв соединения → полупрозрачная плашка «Переподключение…» поверх последнего экрана, ввод блокируется; она держится, пока пул переподключается с бэкоффом, и сменяется плашкой офлайна с «Повторить», только когда пул сдался (`failed`, §6) или соединение отключено приложением (`disconnected`: например, пул заменил его после правки адреса, пользователя или ключа — «Повторить» откроет терминал на новом).
- Канал закрылся, а сессия жива (чужой `attach -d`, например из рецепта agterm на Mac) → один раз молча переподключаемся без `-d`. Если нас выбили повторно в течение минуты → плашка «Отключено другим клиентом» поверх последнего экрана, кнопки «Переподключить» / «Забрать» / «Закрыть» (§6.1).

### 3.6 Настройки

**Серверы** (список, добавить / редактировать / удалить / дублировать):

| Поле | Пример | Обязательно |
|---|---|---|
| Метка | `devbox` | да |
| Адрес (IP или хост) | `203.0.113.10` | да |
| Порт | `22` | да (по умолчанию 22) |
| Пользователь | `ubuntu` | да |
| Ключ | `iPad SE-key` | да |
| Корень проектов | `~/projects` | да (по умолчанию `projects`) |
| Команда запуска | `claude` | да (по умолчанию `claude`) |
| Keepalive, с | `15` | нет |
| Отпечаток хост-ключа | `SHA256:…` (только чтение, кнопка «Сбросить») | — |

Кнопки сервера: **Проверить подключение** · **Подготовить сервер** (установить host-скрипт + `setup`) · **Передать токен Claude** (опционально, аналог `auth`).

**Ключи**: создать (Secure Enclave P-256 или Ed25519) · импортировать (OpenSSH private key, Ed25519) · показать публичный ключ / QR / «Поделиться» · удалить · переключатель «Требовать Face ID для ключей» (§8).

**Терминал**: шрифт (системный моноширинный, Menlo, Courier New), размер, тема (светлая/тёмная/как система), Option = Meta, звук bell.

**Диагностика**: журнал событий SSH и host-скрипта (подключения, реконнекты и их причины, коды выхода exec, таймауты пинга, смена сети) с кнопкой «Поделиться». Без секретов и без содержимого терминала. При такой логике переподключений без журнала не разобрать ни один баг с устройства.

### 3.7 Первый запуск (онбординг)

1. Создать ключ → показать публичный ключ + готовую команду для сервера:
   `mkdir -p ~/.ssh && echo '<pubkey>' >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys`
   (кнопки «Скопировать», «Поделиться» — удобно отправить себе на Mac).
2. Добавить сервер.
3. «Проверить подключение» → первый коннект показывает отпечаток хост-ключа → «Доверять».
4. «Подготовить сервер» → отчёт по чеклисту: tmux ≥ 3.1 ✓, claude в login-PATH ✓, корень проектов ✓, проектов найдено: N.
5. «Готово».

Показывается, пока нет ни ключей, ни серверов и онбординг не пройден; «Пропустить» на любом шаге закрывает его навсегда (флаг `onboarding.done`).

## 4. Технологии

| Слой | Выбор | Почему |
|---|---|---|
| Язык / UI | **Swift 6, SwiftUI**, UIKit где нужно | как agterm; NavigationSplitView даёт сайдбар-дерево из коробки |
| Минимальная ОС | **iPadOS 17** | `@Observable`, актуальный NavigationSplitView |
| Терминал | **[SwiftTerm](https://github.com/migueldeicaza/SwiftTerm)** (MIT) | зрелый VT-эмулятор с готовым `TerminalView` для iOS, мышь, OSC 52, true color; на нём построены коммерческие SSH-клиенты. Версия — 1.99.0 (2026-10-08), закреплена точно (`exactVersion`): с неё drag одним пальцем шлёт колесо (§3.5), и форма колеса — часть контракта с `MouseReport`, поэтому обновление — с перепроверкой; манифест 1.99.0 — `swift-tools-version:6.2`, нужен Xcode 26 |
| SSH | **[Citadel](https://github.com/orlandos-nl/Citadel)** поверх Apple **swift-nio-ssh** | чистый Swift, exec-каналы + PTY на одном соединении, поддерживает Ed25519 и P-256; никакого libssh2/OpenSSL. Проверено 2026-10-20: Citadel 0.12.1 (swift-nio-ssh 0.3.7, swift-nio 2.104.0, swift-crypto 3.15.1) собирается в режиме Swift 6 на Linux aarch64 в образе `swift:6.1-noble`, чистая сборка 6,5 мин на этом хосте. От Citadel ядро берёт разбор и экспорт OpenSSH-ключей; соединение и аутентификацию ядро поднимает на swift-nio-ssh само (`NIOSSHHandler` в инициализаторе своего TCP-канала, свои делегаты ключа и TOFU): `SSHClient.connect(on:settings:)` Citadel 0.12.1 трогает пайплайн не с event loop канала и падает на precondition NIO (проверено 2026-10-20); сами каналы (exec со stdin и EOF для `auth`/установки скрипта, PTY + exec для `attach`) ядро открывает через `NIOSSHHandler.createChannel` напрямую: в публичном API Citadel 0.12.1 `withPTY` открывает только shell, а у `TTYStdinWriter` нет EOF (§5.2) |
| Ключи | **Secure Enclave P-256** (`ecdsa-sha2-nistp256`), запасной вариант Ed25519 в Keychain | ключ SE невозможно извлечь с устройства; swift-nio-ssh принимает SE-ключ напрямую |
| Хранение | Настройки серверов — **Codable JSON** (`servers.json` и `keys.json` в Application Support): `ServerConfig` и `SSHKeyInfo` — Codable-структуры ядра, серверов единицы, а SwiftData потребовал бы дублирующих `@Model`-классов и миграций без выигрыша (решение 2026-10-20); секреты — **Keychain** (`kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`) | |
| Сервер | **bash-скрипт** `tmuxpad-host.sh` (порт `agt-remote-host.sh`) | один round-trip на `list`, логика tmux на стороне сервера, легко отлаживать по ssh руками |
| Тесты | Swift Testing / XCTest; интеграционные — Docker-контейнер с sshd + tmux. Ядро (`TmuxPadCore`) собирается и тестируется на Linux (§5.2) | |
| Сборка / раздача | Xcode, XcodeGen (`project.yml`, как в agterm); TestFlight | бесплатный аккаунт = переподпись раз в 7 дней; для нормальной жизни нужен Apple Developer ($99/год) |

**Рассмотренные альтернативы**

- **libghostty** (как в agterm) — лучший рендеринг, но сборка под iOS и интеграция с UIKit для нас не проверены; оставить как эксперимент после v1, если SwiftTerm не устроит. Абстракция `TerminalSurface` (см. §5) сделает замену локальной.
- **WKWebView + xterm.js** — быстро, но хуже с клавиатурой iPad, IME и производительностью.
- **Форк Blink Shell** — GPL, тянет mosh/libssh2, переделка UI сложнее, чем написать своё.
- **Mosh / Eternal Terminal** — не нужны: устойчивость даёт tmux, а переподключение по SSH через ControlMaster-подобный пул быстрое.

## 5. Архитектура приложения

```
App
├── UI (SwiftUI)
│   ├── SidebarView            дерево Server → Project → Session
│   ├── TerminalScreen         заголовок с [⋯], плашки состояний, чип «Прокрутка ✕»; TerminalView — в TerminalContainerView, который меняет view без пересоздания
```

**Ключевые решения**

- **Одно SSH-соединение на сервер**, внутри — сколько угодно каналов: exec для `list`/`new`/`kill` и PTY-канал на каждую открытую сессию. Аналог `ControlMaster` из рецепта: дерево обновляется за миллисекунды.
- **Открытые терминалы держатся в памяти** (TerminalView + канал) при переключении между ними — переключение мгновенное, без перерисовки. Лимит — 8 открытых на всё приложение, а не на сервер: так соблюдается и предел PTY-каналов на сервер, и память (см. «Лимит каналов»); самые старые неактивные отключаются (detach — на сервере ничего не теряется).
- **Лимит каналов.** sshd по умолчанию пускает 10 сессионных каналов на одно соединение (`MaxSessions 10`), exec-каналы тоже считаются. Поэтому на один сервер — не больше 8 PTY-каналов и не больше 2 одновременных exec: `list`, пинг, `new`, `kill` идут через очередь на 2 слота. Отказ сервера открыть канал показываем как ошибку, а не ждём.
- **Keepalive — прикладной пинг.** В swift-nio-ssh и Citadel keepalive нет, а отправить `keepalive@openssh.com` через публичный API swift-nio-ssh нельзя: из глобальных запросов там доступен только TCP-forwarding. Поэтому `ConnectionPool` раз в `keepaliveSeconds` открывает exec-канал с `true` и ждёт ответа 5 с — вместе с открытием канала; ожидание свободного exec-слота в эти 5 с не входит: занятые слоты значат, что exec идут. Если за этот интервал уже прошёл `list`, пинг пропускается. Два неответа подряд — соединение мёртвое (§6). Обрыв, который заметил сам NIO, приходит раньше через `closeFuture` TCP-канала.
- **Идентификатор устройства** — UUID, создаётся при первом запуске и хранится в Keychain. Передаётся во все exec-строки как `TMUXPAD_CLIENT`, чтобы host-скрипт отличал клиентов этого iPad от чужих (§6.1, §7).
- **PTY**: `TERM=xterm-256color`, `LANG=en_US.UTF-8` env-запросом канала (sshd без `AcceptEnv LANG` его молча отбрасывает, а pam_env может перетереть из `/etc/default/locale`; fallback через `env` в команде пока не делается), размер из TerminalView; команда канала — `attach NAME` в форме ниже.
- **Форма exec-строк**: `env TMUXPAD_CLIENT='…' TMUXPAD_PROJECTS='…' TMUXPAD_CMD='…' "$HOME"/.local/bin/tmuxpad-host.sh <cmd> <args>`. `env` не зависит от синтаксиса login-шелла пользователя (csh не понимает `VAR=x cmd`), `$HOME` разворачивает шелл, который sshd запускает для команды. Значения — в одинарных кавычках после валидации (§8).
- **Одно окно.** `UIApplicationSupportsMultipleScenes = false`: второе окно в Stage Manager означало бы два `attach` одной сессии с одного устройства и второй набор каналов.
- **Протокол `TerminalSurface`** (feed bytes / send input / resize / delegate) — чтобы SwiftTerm можно было заменить libghostty без переделки остального.

### 5.2 Разделение по платформам сборки

Слой Core живёт отдельным SwiftPM-пакетом **`TmuxPadCore`** без `import UIKit`/`SwiftUI`, приложение в Xcode подключает его как зависимость. ## 6. Жизненный цикл соединения (главное ограничение iPadOS)

iPadOS замораживает приложение в фоне; сокеты умирают в течение ~30 с (в Split View/Stage Manager приложение остаётся активным, пока видно на экране). Устойчивость обеспечивает **tmux на сервере**, приложение лишь переподключается.

| Событие | Поведение |
|---|---|
| `scenePhase → .background` | Опрос дерева останавливается сразу; `beginBackgroundTask` (до ~30 с работы), через 25 с (или по истечении фоновой задачи, или при смене сети в фоне — сразу) соединения закрываются. Если вернулись раньше — ничего не рвём |
| `scenePhase → .active` | Для каждого сервера с открытыми сессиями: reconnect → `list` → для каждой открытой сессии, которая ещё существует, новый PTY-канал `attach` (без `-d`, tmux отдаёт полный экран); исчезнувшие получают заглушку «Сессия завершена». Чужие клиенты не мешают (§6.1). Плашка «Переподключение…» на время |
| Смена сети (`NWPathMonitor`) | Принудительный reconnect, не дожидаясь keepalive-таймаута: рвётся и соединение, которое выглядит живым (`ConnectionPool.reconnectAll(force: true)`) — старый сокет после смены сети остаётся «активным», пока его не похоронит keepalive |
| Ключ не принят / хост-ключ сменился | Сразу `failed`, без бэкоффа: повтор это не лечит |
| Пинг не ответил 2 раза подряд (§5) | Соединение мёртвое → reconnect с бэкоффом 1 → 2 → 5 → 10 с (аналог `AGT_REMOTE_RETRY`); после четырёх неудачных попыток пул останавливается в состоянии `failed` и ждёт явного запроса (возврат из фона, смена сети, кнопка «Повторить») — иначе в офлайне батарея уходила бы на бесконечные попытки |
| Канал закрылся с выходом 0, приложение detach не делало | Проверяем `list`: сессии нет → заглушка «Сессия завершена»; сессия есть → нас выбил чужой `attach -d`: один раз переподключаемся молча, при повторе в течение минуты — плашка «Отключено другим клиентом» (§6.1) |
| Сервер недоступен | Сервер в дереве `⚠ offline`, прочие работают; открытые терминалы этого сервера — плашка с кнопкой «Повторить» |

### 6.1 Кто владеет сессией

У tmux ≥ 3.1 опция `window-size` по умолчанию `latest`: окно берёт размер клиента с последней активностью. Поэтому к сессии могут быть подключены iPad и Mac одновременно, и «сжатия» окна, ради которого рецепт делает `attach -d`, не происходит; зависший после сна клиент iPad ничего не вводит и размер не диктует. Правило: **приложение подключается без `-d` и выкидывает только собственных клиентов этого устройства; чужой клиент выкидывается только по явному действию пользователя («Забрать»).**

- `attach NAME` перед `exec tmux attach-session -t =NAME` делает `detach-client` для клиентов сессии, у которых PID-файл в `~/.tmuxpad/clients/` содержит текущий `TMUXPAD_CLIENT` (зависшие клиенты этого же iPad), и выставляет `window-size latest` на каждом окне сессии — на случай, если пользователь глобально поставил `smallest`.
- Возврат из фона, смена сети, перезапуск приложения: переподключаемся ко всем открытым сессиям молча, независимо от `others`.
- Канал `attach` закрылся с 4 → «Сессия завершена». С иным ненулевым кодом при живой сессии или при отказе открыть PTY (`channelRefused`, неверное имя) — плашка офлайн с «Повторить», без автоповторов: имя, окружение, скрипт повтором не лечатся. Канал без exit-status считается как 0.
- Нас выбил чужой `attach -d` (канал закрылся с 0, сессия жива): один раз переподключаемся молча. Если это повторилось в течение минуты, на другом устройстве нас выбивают намеренно: плашка «Отключено другим клиентом», кнопки «Переподключить» / «Забрать» (`take`) / «Закрыть».
- «Забрать» в контекст-меню сессии и в меню `[⋯]` — единственный путь к `attach -d` (`take` в §7). Тап по сессии в дереве и мастер «Подключиться» делают обычный `attach`.
- Бейдж `attached` в дереве информационный: рядом работает кто-то ещё.
- Цена подхода: когда печатают с Mac, окно принимает размер Mac, и на iPad появляется незаполненная область до следующего ввода с iPad. Осознанный компромисс в пользу «никого не выбиваем».

Почему нельзя считать чужих просто по `session_attached`: после сна iPad сервер ещё долго держит его мёртвое соединение. Без `ClientAliveInterval` в sshd это до TCP-таймаута, то есть часы. Всё это время tmux считает старый клиент iPad подключённым, и сессия выглядела бы занятой «кем-то». Поэтому host-скрипт помечает клиентов приложения (`attach` в §7), `list` считает только чужих, а `attach` выкидывает своих зависших. Чистое закрытие соединения при уходе в фон (§6) делает зависшие клиенты редкостью: они остаются только после убийства приложения системой или обрыва сети.

## 7. Серверная часть: `tmuxpad-host.sh`

Порт `agt-remote-host.sh` (MIT, с атрибуцией). Ставится в `~/.local/bin/tmuxpad-host.sh`, состояние в `~/.tmuxpad/`. **Совместимость с рецептом agterm не нужна** — свои пути, свои форматы, никаких оглядок на `~/.agt-remote`.

```
tmuxpad-host.sh version              → "tmuxpad-host 1"         (проверка/обновление скрипта)
tmuxpad-host.sh list                 → TSV, см. ниже
tmuxpad-host.sh new NAME PROJECT     → создать tmux-сессию, запустить агента; exit 3 если уже есть
tmuxpad-host.sh attach NAME          → выкинуть своих зависших клиентов, exec tmux attach-session -t =NAME; exit 4 если нет
tmuxpad-host.sh take NAME            → то же, но attach-session -d: выкидывает всех (кнопка «Забрать»)
tmuxpad-host.sh copy-cancel NAME     → tmux send-keys -t '=NAME:' -X cancel; exit 0 и вне copy-mode, 2 — неверное имя (§3.5)
tmuxpad-host.sh kill NAME            → убить сессию и её state-файлы
tmuxpad-host.sh setup                → идемпотентная подготовка, отчёт-чеклист
tmuxpad-host.sh auth                 → токен Claude со stdin → ~/.tmuxpad/env (0600)
tmuxpad-host.sh doctor               → проверки: tmux≥3.1, claude в login PATH, корень проектов
```

Переменные из окружения команды (приложение передаёт их явно в exec-строке): `TMUXPAD_PROJECTS`, `TMUXPAD_CMD`, `TMUXPAD_CLIENT` (UUID устройства, §5; скрипт проверяет его по regex UUID).

Уточнения при реализации (план `docs/plans/completed/20261020-host-script.md`, решения 5–8):
- коды выхода: 2 — неверные аргументы, имена или окружение (в том числе `list` без корня проектов, `attach`/`take` без `TMUXPAD_CLIENT`); 3 — `new`, сессия уже есть (в том числе если параллельный `new` с тем же именем успел первым); 4 — `attach`/`take`, сессии нет; `kill` несуществующей сессии и `copy-cancel` вне copy-mode — 0; прочие ошибки tmux и записи файлов состояния (`new`, `auth`) — 1;
- `TMUXPAD_CLIENT` обязателен для `attach` и `take`; `list` без него считает всех клиентов чужими;
- флаги `-n`/`--session-id`/`--resume` добавляются, только если basename первого слова `TMUXPAD_CMD` — `claude`; иная команда запускается как есть, `NAME.claude` не создаётся;
- `doctor` — TSV `ok|warn|fail<TAB>KEY<TAB>MESSAGE` (ключи `tmux`, `claude`, `claude_name`, `projects`, `script`), код 1 при любом `fail`; отсутствие `--name` у claude — `warn`; строка `claude_name` есть, только когда команда — `claude` и он найден: при своей `TMUXPAD_CMD` — `ok claude custom command` без `claude_name`, при ненайденном claude — `fail claude`;
- `list` пропускает сессии с именем, не проходящим валидацию (сделанные руками, например `my work`): `attach`/`kill` их всё равно не примут;
- `new` на stdout ничего не печатает: контракт — состояние на диске и код выхода.

**`attach NAME`** по шагам:
1. `TERM`, который не знает `infocmp`, заменяется на `xterm-256color` (с ним падает любая команда tmux, `has-session` тоже); `tmux has-session -t =NAME` → иначе `exit 4`;
2. чистка: файлы в `~/.tmuxpad/clients/`, PID-ов которых нет в `tmux list-clients`, удаляются (то же делает `list`); исключения — PID, который ещё исполняет сам скрипт до `exec` (`/proc/<pid>/cmdline` содержит `tmuxpad-host`), и PID, который уже tmux-клиент после `exec`, но сервер его ещё не перечислил (`/proc/<pid>/comm` — `tmux` или `tmux: client`, tmux переименовывает клиента сразу после старта): иначе `list` или `attach`, идущие параллельно с `attach`, сняли бы метку с клиента;
3. свои зомби: `tmux list-clients -t =NAME -F '#{client_pid}\t#{client_tty}'`, для PID-ов, чей файл содержит текущий `TMUXPAD_CLIENT`, — `tmux detach-client -t <tty>`;
4. `tmux set -t =NAME: mouse on` и `tmux set -w -t <окно> window-size latest` для каждого окна из `tmux list-windows -t =NAME`;
5. UUID устройства → `~/.tmuxpad/clients/$$`; из-за `exec` PID tmux-клиента совпадает с `$$`, так что файл однозначно связывает клиента tmux с устройством;
6. `exec tmux attach-session -t =NAME`.

**`take NAME`** — те же шаги с `attach-session -d`.

Таргеты pane и окна, а также `set`/`show` любых опций (включая session-опцию `mouse`) — `=NAME:`: голый `=NAME` даёт `can't find pane` или `no such session` (проверено на 3.4). Для `has-session`, `attach-session`, `kill-session`, `list-clients -t`, `list-windows -t` — `=NAME`.

**`list`** — расширенный формат (версионированный заголовок, чтобы менять без поломок):
```
V	1
S	<name>	<others>	<project>	<activity_epoch>
P	<project>	<abs_path>
```
tmux-формат сессий: `#{session_name}\t#{session_path}\t#{session_activity}`; фильтр «path лежит прямо в корне проектов» — как в рецепте, но корень и родитель `session_path` сравниваются после `realpath`, иначе симлинк в пути ломает фильтр; последний компонент не раскрывается, поэтому проект-симлинк остаётся под своим именем. `activity` нужен приложению для сортировки сессий в мастере «Подключиться» и подписи «активность N мин назад». `others` — число клиентов сессии из `tmux list-clients -F '#{session_name}\t#{client_pid}'`, у которых нет файла в `~/.tmuxpad/clients/` с текущим `TMUXPAD_CLIENT`. Клиенты рецепта agterm и обычного `tmux attach` с Mac всегда чужие.

**`new NAME PROJECT`** — по шагам из запроса:
1. валидация имени и проекта, проверка `[[ -d $PROJECTS/$PROJECT ]]`;
2. `tmux has-session -t =NAME` → если есть, `exit 3` (приложение предложит подключиться); если `new-session` на шаге 3 упал, а сессия уже есть (гонка двух `new`) — тоже `exit 3`;
3. `pane=$(tmux new-session -d -P -F '#{pane_id}' -s NAME -c DIR)` — tmux-сессия с именем, сразу в папке проекта; затем `tmux set -t =NAME: mouse on`;
4. UUID разговора: `~/.tmuxpad/NAME.claude` — строка `<uuid>\t<project>`, создаётся при первом `new`, хранится до `kill`. Если файл есть, но проект в нём другой (сессию убили руками через tmux и создали с тем же именем в другом проекте) — новый UUID и перезапись файла: Claude Code резюмит по UUID из любого каталога (проверено на 2.1.304), и без этого в новый проект приехал бы разговор старого. Источник UUID — `/proc/sys/kernel/random/uuid` (есть на любом Linux), `uuidgen` не нужен;
5. `tmux send-keys -t $pane "sh -c '[ -f ~/.tmuxpad/env ] && . ~/.tmuxpad/env; exec $CMD <флаги>'" Enter` — claude стартует внутри login-шелла, поэтому его выход не убивает tmux-сессию.

**Имя Claude-сессии = имя tmux-сессии.** Claude Code умеет задавать имя при старте: `claude -n NAME` (`--name`); оно видно в строке промпта, в `/resume`-пикере и работает как `claude --resume NAME`. Флаги запуска:

| Ситуация | Команда |
|---|---|
| Новая сессия | `claude -n NAME --session-id <uuid>` |
| Сессия пересоздаётся (ребут сервера), транскрипт `~/.claude/projects/*/<uuid>.jsonl` есть | `claude --resume <uuid>` (имя хранится в самом разговоре). Каталог транскрипта — абсолютный путь проекта, где `/` и `.` заменены на `-`; искать можно глобом, `--resume` всё равно находит транскрипт из любого каталога (проверено на 2.1.304) |
| Транскрипта нет (удалён / истёк срок хранения 30 дней) | как новая, с **новым** UUID и перезаписью `NAME.claude` — одно правило на оба случая «другой проект» и «нет транскрипта». Занятый `--session-id` ошибки не даёт (проверено на 2.1.304), но два транскрипта с одним ID в разных каталогах путают `--resume` |

Почему резюмим по UUID, а не `--resume NAME`: имя может совпасть с разговором, начатым руками в том же проекте, и тогда вместо резюма откроется пикер; UUID однозначен. Если сессию переименовали изнутри (`/rename`), имя tmux-сессии в дереве остаётся прежним — источником правды для приложения служит tmux.

В фазе 0 проверить на серверах версию Claude Code (`claude --version`) и что `-n` вместе с `--session-id` принимается; если сервер на старой версии без `-n` — `doctor` предупреждает, сессия стартует без имени.

Разделение `new` и `attach` (в рецепте это одна команда) нужно, чтобы приложение отличало «создал» от «подключился» и корректно показывало конфликт имён.

**`setup`** пишет в `~/.tmux.conf` помеченный идемпотентный блок: `set-clipboard on`, `history-limit 50000`, и `allow-passthrough on` только при `tmux -V` ≥ 3.3. Если tmux-сервер уже запущен, при добавлении блока те же опции ставятся ему через `tmux set -g`: конфиг он прочитал до блока. Глобально `mouse` **не** включает: это сломало бы выделение мышью в tmux-сессиях пользователя на Mac; `mouse` — session-опция, её ставят `new` и `attach` на конкретную сессию. `~/.profile` не трогает: `new` сам сорсит `~/.tmuxpad/env`. Не трогает `~/.claude/settings.json` (хуки статуса — бэклог), `known_hosts` и ssh-agent.

**Установка из приложения**: exec `mkdir -p ~/.local/bin && cat > ~/.local/bin/.tmuxpad-host.sh.tmp && [ "$(wc -c < …tmp)" -eq <размер> ] && chmod +x …tmp && mv -f …tmp ~/.local/bin/tmuxpad-host.sh` со скриптом в stdin, затем `setup`. Временный файл и сверка размера — потому что оборванный посреди передачи канал даёт `cat` обычный EOF: без них на сервере остался бы обрубок скрипта, у которого `version` молчит. При каждом подключении `version` → если старше бандла, предложить обновить.

**Требования к серверу**: Linux, bash, tmux ≥ 3.1 (нужен `window-size latest`; Ubuntu 22.04 с 3.2a подходит, `allow-passthrough` ставится только от 3.3), Claude Code в PATH login-шелла и залогинен (`claude` → `/login` или `auth` с токеном из `claude setup-token`), sshd с разрешённым входом по ключу `ecdsa-sha2-nistp256` или `ssh-ed25519` (по умолчанию в OpenSSH — да). Для `git push` из сессии — собственный ключ/`gh auth` на сервере (агента с iPad не пробрасываем).

## 8. Безопасность

- Приватный ключ: Secure Enclave (неизвлекаемый) или Keychain `ThisDeviceOnly`; никогда не логируется, не попадает в бэкапы.
- Опционально (`security.requireBiometrics`, по умолчанию выключено): Face ID перед первым использованием ключа после запуска и после возврата из фона — `LAContext.deviceOwnerAuthentication`, один механизм для SE и Ed25519. Переключатель, включённый посреди сессии, спросит Face ID со следующего возврата из фона или запуска. Ключи кешируются по `keyID`, кеш чистится при уходе в фон. Пул переподключается с сохранённым `SSHAuth`, поэтому проверку перед переподключением делает `LifecycleCoordinator`, а не только `auth(for:)`; собственный цикл реконнекта пула (обрыв, пропущенный пинг) перед каждой попыткой ждёт, пока ключ закрыт (`reconnectGate` → `KeyUnlocker.waitUntilUnlocked`), и сам запрос не показывает; после отказа ждать перестаёт — соединение в «Ошибка», у терминала «Повторить», а не вечное «Переподключение…». Отказ — «Доступ к ключу отменён», соединения и опрос дерева не поднимаются, пока Face ID не пройден снова: «Повторить» у терминала или любое действие с ключом (открытие сессии, обновление дерева, мастер); смена сети до этого ничего не переподключает, автоповторов нет. Уже живые соединения отказ не рвёт.
- Хост-ключ: TOFU с явным подтверждением отпечатка: ядро при первом подключении само сохраняет отпечаток и подключается, UI показывает «Доверять», пока отпечаток соединения не совпадает с подтверждённым в `ServerConfig.hostKeyFingerprint` (не только при `ServerConnection.hostKeyFirstSeen`: вопрос без ответа — приложение закрыли, соединение переподключилось — не считается согласием), отказ → `disconnect()` + `HostKeyStore.reset(host:port:)`. Доверие в `HostKeyStore` хранится по `host:port` и общее у серверов с одним адресом: копия сервера, чей отпечаток уже подтверждён у другого сервера с тем же адресом, подключается без вопроса; удаление сервера сбрасывает доверие, только если адрес больше никем не используется; смена адреса или порта очищает отпечаток в конфиге; «Сбросить» в форме сервера применяется сразу и очищает отпечаток у всех серверов с этим адресом (отпечаток — `SHA256:<base64 без '='>` от wire-формата ключа, как печатает OpenSSH); смена отпечатка → блокирующее предупреждение, подключение только после ручного «Сбросить»; сменой считается и несовпадение с непустым подтверждённым отпечатком в конфиге (у копии без своего отпечатка — в конфиге другого сервера с тем же адресом), когда `HostKeyStore` ключа не знал (бэкап восстановлен на новом iPad, доверие по адресу сбросили у другого сервера): соединение рвётся, в `HostKeyStore` возвращается подтверждённый отпечаток.
- Без паролей в v1 (только ключи) — меньше поверхность и не надо хранить пароли.
- Имена сессий/проектов валидируются и в приложении, и в скрипте; в exec-строки ничего не подставляется без экранирования (одинарные кавычки + запрет `'`, как в рецепте).
- Токен Claude (`auth`) передаётся через stdin, не в аргументах; на сервере `0600`.
- Терминал: OSC 52 с сервера только пишет в буфер обмена iPad (не-UTF-8 отбрасывается), запрос чтения буфера не выполняется; ссылки из терминала открываются только для `http`/`https`.

## 9. Обработка ошибок (что видит пользователь)

| Ситуация | Сообщение / действие |
|---|---|
| Ключ не принят | В дереве у сервера «Сервер не принял ключ» → «Проверить»; в проверке — кнопка «Показать публичный ключ»; автоповторов нет |
| Хост-ключ изменился | В дереве у сервера «Ключ сервера изменился» → «Проверить»; в проверке — блокирующий алерт с обоими отпечатками |
| Отпечаток не подтверждён | В дереве: «Подключение не проверено» → «Проверить» (там «Доверять»); опрос и действия над сессиями к серверу не подключаются |
| Нет host-скрипта / старая версия | Сервер в дереве: «Требуется подготовка» → «Проверить» (там «Подготовить») |
| tmux < 3.1 / нет claude | Отчёт `doctor` с конкретной строкой |
| Нет проектов | В мастере: «В `~/projects` нет папок» |
| Имя занято | «Сессия `X` уже есть» → [Подключиться] [Другое имя] |
| Неверное имя | Подсветка поля + допустимые символы |
| Сервер оффлайн | `⚠` и «Нет связи» у сервера, кнопка «Повторить»; последний снимок дерева серым с подписью «по состоянию на HH:mm» |

## 10. Бэклог (после v1)

1. **Индикатор статуса агента** (active / blocked / done) в дереве.
   Предлагаемый подход проще моста из рецепта: хуки Claude Code на сервере вызывают `tmuxpad-host.sh status <state>`, который делает `tmux set-option -t <сессия> @tmuxpad_status <state>`; `list` отдаёт `#{@tmuxpad_status}` дополнительной колонкой; приложение и так опрашивает `list`. Без `ssh -R`, без python-relay, работает и при нескольких клиентах. `setup` научится мержить хуки в `~/.claude/settings.json` (логика `merge_hooks` из рецепта).
2. **Уведомления, когда агент ждёт** — нужен внешний пуш (ntfy.sh или свой APNs-relay), т.к. в фоне приложение не держит соединение.
3. Клонирование репозитория в корень проектов из приложения (`clone`), создание пустого проекта.
4. Дашборд — сетка превью сессий (`tmux capture-pane -p`), как dashboard в agterm.
5. Синхронизация серверов через iCloud (без ключей).
6. Jump-host / ProxyJump, вход по паролю, нестандартные ssh-опции.
7. libghostty вместо SwiftTerm.
8. Sync `~/.claude` (CLAUDE.md, skills) на сервер — аналог `sync` из рецепта; источника на iPad нет, так что скорее «с сервера на сервер».
9. Scratch-терминал (обычный шелл в проекте без tmux) поверх сессии.

## 12. Риски

| Риск | Вероятность | Митигирование |
|---|---|---|
| Ввод в SwiftTerm с аппаратной клавиатурой iPad (Esc, Ctrl, IME) имеет шероховатости | средняя | проверить в фазе 0; `pressesBegan` для недостающих клавиш; запасной вариант — libghostty |
| API Citadel для PTY меняется между версиями | средняя | зафиксировать версию; узкий адаптер `SSHTransport` поверх swift-nio-ssh |
| Сервер не принимает ECDSA P-256 | низкая | Ed25519 как альтернативный тип ключа |
| Фоновые ограничения iPadOS раздражают частыми переподключениями | высокая (by design) | быстрый reconnect + tmux; mosh в бэклог только если будет реально мешать |
| Подпись: без платного аккаунта приложение живёт 7 дней | — | Apple Developer Program или переустановка из Xcode |

## 13. Открытые вопросы

1. Распространение: только для себя (Xcode/TestFlight) или App Store — влияет на онбординг и требования к приватности.

**Решено:**
- Совместимость с рецептом agterm не нужна; Claude-сессия получает имя tmux-сессии через `claude -n NAME`.
- 2026-10-20: `attach` без `-d`, чужих выкидывает только `take` по кнопке «Забрать»; размер окна отдаём `window-size latest` (§6.1).
- 2026-10-20: выход из copy-mode — `copy-cancel` на стороне приложения перед первым вводом после скролла; биндинги tmux не трогаем (§3.5).
- 2026-10-20: порог tmux 3.1 вместо 3.3, `allow-passthrough` условно (§7).
- 2026-10-20: `mouse on` только на сессиях приложения, `setup` не трогает `~/.profile` и глобальный `mouse` (§7).
- 2026-10-20: `NAME.claude` хранит проект; смена проекта или потеря транскрипта → новый UUID (§7).
- 2026-10-20: одно окно приложения, exec-строки через `env`, журнал диагностики в v1 (§5, §3.6).
- 2026-10-20: ядро — пакет в `TmuxPadCore/` со скриптом-ресурсом; соединение и каналы SSH — на swift-nio-ssh напрямую (`NIOSSHHandler` в своём TCP-канале), от Citadel только разбор и экспорт OpenSSH-ключей, всё за протоколом `SSHTransport`; реконнект останавливается после четырёх попыток до явного запроса (§4, §5.2, §6).
- 2026-10-20: SwiftTerm от 1.99.0 (колесо одним пальцем); мышиные отчёты идут в PTY мимо `copy-cancel`, разбор — `MouseReport` в ядре; панель клавиш — встроенная `TerminalAccessory` (§3.5, §4).
- 2026-10-21: SwiftTerm закреплён точной версией 1.99.0; OSC 52 только на запись, ссылки — только `http`/`https` (§3.5, §4, §8).
- 2026-10-20: серверы и метаданные ключей — Codable JSON, не SwiftData; лимит 8 открытых терминалов — на всё приложение; логика State без view (`TreeRefresher`, `OpenSessionsRoster`, `SessionTree`) — в ядре, приложение оборачивает её в `@Observable` (§4, §5, §5.2).
